# MVP 手动验收清单

本文档用于验证 Chrome 插件 MVP 是否达到可演示状态。

## 1. 插件加载

1. 执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start-chrome-dev.ps1
   ```

2. 确认 Chrome 打开后能看到插件侧边栏或扩展页面。
3. 如果脚本没有自动打开侧边栏，进入 `chrome://extensions` 手动加载当前插件目录。

验收标准：

- 插件能加载成功。
- 点击插件图标能打开侧边栏。
- 侧边栏初始状态能提示配置 API Key 或显示已加载配置。

## 2. 模型设置

1. 打开插件设置页。
2. 填写 API Key、Base URL 和模型名称。
3. 点击“保存”。
4. 点击“测试连接”。

验收标准：

- 设置能保存到浏览器本地。
- 连接成功时显示“连接成功”。
- Key 错误或 Base URL 错误时能显示失败原因。

## 3. 信息不足时追问

输入：

```text
帮我设计登录测试用例。
```

验收标准：

- 模型先提出关键澄清问题。
- 不生成重复或泛泛的测试用例表格。
- 该会话出现在“历史”中，并标记为尚未生成用例。

## 4. 信息充分时生成用例

输入：

```text
手机号+密码登录。手机号必须为中国大陆 11 位手机号，密码长度 8-20 位。连续输错密码 5 次后账号锁定 30 分钟。登录成功后进入首页，请设计测试用例。
```

验收标准：

- 生成结构化测试用例表格。
- 用例包含编号、需求点、依据、风险、测试方法、标题、优先级、类型、前置条件、测试步骤、预期结果。
- 覆盖主流程、输入校验、异常流程、边界值和账号锁定状态。
- 点击“历史”后能重新打开该会话和用例表格。

## 4.1 单点场景缺少真实信息时必须追问

输入：

```text
手机号+密码登录成功
```

验收标准：

- 不应编造账号状态、密码规则、登录成功跳转或页面反馈。
- 缺少真实执行信息时，应先追问用户补充，并返回空的 cases 数组。
- 追问必须列出具体问题，不能只写“需要澄清以下问题”。
- 用户补充真实规则和成功判定后，再生成登录成功路径相关用例。

## 5. 复杂需求覆盖

输入：

```text
电商优惠券结算。用户可领取满 100 减 20 优惠券，每个订单只能使用一张，优惠券不可与会员折扣叠加。订单取消后优惠券退回，支付超时 15 分钟自动取消。请设计测试用例。
```

验收标准：

- 用例覆盖满减门槛、不可叠加、订单取消、支付超时、优惠券退回。
- 步骤和预期结果具体可执行。
- 不出现“验证功能正常”这类模糊描述。

## 6. 导出

在已生成测试用例后，点击 XMind Markdown。

验收标准：

- XMind Markdown 文件能下载。
- 中文内容不乱码。
- XMind Markdown 是层级结构：需求 -> 用例类型 -> 用例 -> 优先级/前置条件/步骤/预期。

## 7. 兼容服务失败提示

如果 OpenAI 兼容服务不支持严格 JSON Schema 输出：

1. 保持“使用严格 JSON Schema 输出”开启。
2. 发送一条可生成用例的需求。
3. 观察错误提示。
4. 关闭“使用严格 JSON Schema 输出”后重试。

验收标准：

- schema 或 response_format 相关错误能提示关闭严格 JSON Schema 输出。
- 关闭后能继续使用 JSON object 模式请求模型。

## 8. 生成质量检查

使用“手机号+密码登录”和“电商优惠券结算”两个样例各生成一次。

验收标准：

- 生成结果下方显示“本地结构审查”。
- 如果用例字段完整、标题不重复、步骤和预期足够具体，应显示未发现明显问题。
- 如果模型生成重复标题、空字段、过短步骤或模糊预期，应显示具体提示。
- 质量提示不阻断 XMind Markdown 导出。

## 8.1 独立 AI 复审

在已经生成测试用例后点击“AI 复审”。

验收标准：

- 复审期间按钮和发送输入进入不可重复提交状态。
- 复审结果包含 0-100 分评分和摘要。
- 有问题时标明风险等级、关联用例编号、问题与修改建议。
- 只把需求明确支持但未覆盖的测试点列为“待补覆盖”，不编造新业务规则。
- 模型或结构化输出失败时展示错误，不丢失原用例。

## 8.2 人工评审与采纳

验收标准：

- 单条用例可采纳、取消采纳、编辑、标记问题和删除。
- 编辑后用例回到“待评审”，旧 AI 复审结果失效。
- 标记问题后显示评审意见并进入“待修改”。
- 历史记录重新打开后保留评审状态和意见。
- “导出已采纳”只包含已采纳用例，并包含需求点、依据、风险和测试方法。

## 9. 登录样例质量标准

输入：

```text
手机号+密码登录。手机号必须为中国大陆 11 位手机号，密码长度 8-20 位。连续输错密码 5 次后账号锁定 30 分钟。登录成功后进入首页，请设计测试用例。
```

验收标准：

- 至少覆盖登录成功。
- 至少覆盖手机号为空、格式错误或长度错误。
- 至少覆盖密码为空、低于 8 位或超过 20 位。
- 至少覆盖错误密码。
- 至少覆盖连续输错 5 次锁定账号。
- 至少覆盖锁定期间再次登录。
- 至少覆盖 30 分钟后解锁或可重新登录。
- 每条用例的预期结果能判断通过或失败。

## 10. 优惠券样例质量标准

输入：

```text
电商优惠券结算。用户可领取满 100 减 20 优惠券，每个订单只能使用一张，优惠券不可与会员折扣叠加。订单取消后优惠券退回，支付超时 15 分钟自动取消。请设计测试用例。
```

验收标准：

- 至少覆盖订单金额等于 100、低于 100、高于 100。
- 至少覆盖每个订单只能使用一张优惠券。
- 至少覆盖优惠券不能与会员折扣叠加。
- 至少覆盖订单取消后优惠券退回。
- 至少覆盖支付超时 15 分钟自动取消。
- 至少覆盖重复使用优惠券或已使用优惠券不可再次使用。
- 至少覆盖订单金额、优惠券状态和订单状态一致性。
