# AI 测试用例生成质量提升计划

本文档用于指导后续提升“需求文案 -> 测试用例”的生成质量。目标不是让模型生成更多内容，而是让输出更可执行、更少重复、更能覆盖真实风险。

## 1. 质量目标

当前 MVP 的核心目标：

```text
用户输入需求
  -> AI 判断信息是否足够
  -> 信息不足时追问
  -> 信息足够时生成结构化测试用例
  -> 用户可查看、修改配置，并导出用例
```

下一阶段质量目标：

- 需求不清楚时，不硬生成用例。
- 需求清楚时，用例覆盖主流程、异常、边界、状态、权限、安全、数据一致性。
- 每条用例都有明确前置条件、步骤和预期结果。
- 用例之间不大量重复。
- 输出能被测试人员直接评审、复制或导入测试管理工具。

## 2. 质量评估标准

每次生成结果按 6 个维度评估：

| 维度 | 合格标准 |
| --- | --- |
| 清晰度 | 用户能看懂每条用例在验证什么 |
| 可执行性 | 步骤具体，测试人员可以照着执行 |
| 可判断性 | 预期结果能判断通过或失败 |
| 覆盖度 | 覆盖主流程、异常、边界、状态变化和关键风险 |
| 去重度 | 没有为了凑数量生成高度相似用例 |
| 结构化 | 字段完整，便于导出和后续处理 |

建议内部评分：

```text
总分 100
- 需求理解与追问：20
- 覆盖完整性：25
- 可执行性：20
- 预期结果质量：15
- 去重与优先级：10
- 结构化稳定性：10
```

## 3. 第一轮改造：加强提示词

目标：先用最低成本提高生成稳定性。

实施项：

1. 把系统提示词拆成更明确的任务步骤：
   - 先判断需求信息是否足够。
   - 不足时只追问关键问题，`cases` 返回空数组。
   - 足够时按测试设计方法生成用例。

2. 增加覆盖清单：
   - 主流程
   - 输入校验
   - 异常流程
   - 边界值
   - 状态流转
   - 权限与安全
   - 数据一致性
   - 外部接口异常

3. 增加禁止项：
   - 不要写“验证功能正常”。
   - 不要重复生成只改标题的用例。
   - 不要在信息不足时猜业务规则。
   - 不要输出 Markdown 或代码块。

验收标准：

- 样例“帮我设计登录测试用例”会先追问。
- 样例“手机号密码登录”能覆盖锁定前后状态。
- 样例“优惠券结算”能覆盖金额、状态、超时和取消。

## 4. 第二轮改造：增加生成模式

目标：让用户能按不同质量方向继续迭代。

建议新增 4 个操作：

| 操作 | 作用 |
| --- | --- |
| 补充边界 | 在已有用例基础上补边界值 |
| 补充异常 | 补充失败、超时、接口异常、权限异常 |
| 压缩重复 | 合并重复或高度相似用例 |
| 质量自检 | 让 AI 检查当前用例缺口 |

实现方式：

- 不新增复杂页面。
- 在生成结果下方增加操作按钮。
- 按钮复用当前会话上下文，追加一条明确指令给模型。

验收标准：

- 点击“补充边界”后，只新增边界相关用例。
- 点击“压缩重复”后，不应扩大用例数量。
- 点击“质量自检”后，输出缺口清单或改进后的用例。

## 5. 第三轮改造：需求点映射

目标：让测试用例能被评审。

建议把结构从：

```json
{
  "id": "TC-001",
  "title": "...",
  "priority": "P0",
  "type": "...",
  "precondition": "...",
  "steps": "...",
  "expected": "..."
}
```

扩展为：

```json
{
  "id": "TC-001",
  "requirementPoint": "连续输错 5 次后账号锁定 30 分钟",
  "title": "...",
  "priority": "P0",
  "type": "...",
  "precondition": "...",
  "steps": "...",
  "expected": "...",
  "risk": "账号安全与暴力破解"
}
```

收益：

- 能看出每条用例覆盖哪个需求点。
- 方便发现需求点未覆盖。
- 方便后续导出到测试管理平台。

风险：

- Schema 变复杂后，对部分 OpenAI 兼容服务更容易失败。
- 应先保留旧字段，新增字段作为可选字段。

## 6. 第四轮改造：质量自检器

目标：生成后自动检查一次，而不是完全信任第一次输出。

流程：

```text
第一次生成用例
  -> 插件检查字段完整性和重复标题
  -> AI 自检覆盖缺口
  -> 必要时提示用户补充或一键优化
```

插件侧可先做确定性检查：

- `cases` 是否为空。
- 必填字段是否缺失。
- 标题是否重复。
- 步骤或预期是否过短。
- 是否出现“正常”“符合预期”这类模糊表达。

AI 侧做语义检查：

- 是否遗漏边界值。
- 是否遗漏状态流转。
- 是否遗漏权限、安全、数据一致性。
- 是否存在重复用例。

## 7. 推荐实施顺序

第一优先级：

1. 升级 `prompts.js`，明确生成步骤、覆盖清单和禁止项。
2. 增加样例需求的手动验收。
3. 增加本地字段完整性检查。

第二优先级：

1. 增加“补充边界 / 补充异常 / 压缩重复 / 质量自检”按钮。
2. 优化导出 Markdown，增加需求点和风险信息。
3. 增加历史会话的重新生成能力。

第三优先级：

1. 增加需求点映射字段。
2. 增加质量评分。
3. 增加导出模板适配。

暂不建议近期做：

- Jira / 禅道 API 回写。
- RAG 知识库。
- OCR 截图识别。
- 当前页面 DOM 自动分析。

这些能力有价值，但会把问题从“生成质量”扩大成“系统集成”，不适合当前阶段。

## 8. 第一轮可执行任务

下一步建议直接实施：

1. 更新 `prompts.js`：
   - 明确“先判断，再追问或生成”。
   - 增加覆盖清单。
   - 增加用例质量要求。

2. 更新 `sidepanel.js`：
   - 在生成结果后做本地质量检查。
   - 如果发现字段缺失、标题重复、步骤过短，在界面显示提示。

3. 更新 `docs/验收清单.md`：
   - 增加生成质量验收项。
   - 用固定样例验证追问、边界、状态、异常和去重。

第一轮成功标准：

- 信息不足样例不会直接生成用例。
- 登录样例至少覆盖成功、手机号校验、密码边界、错误密码、锁定、锁定后登录、解锁后登录。
- 优惠券样例至少覆盖门槛边界、不可叠加、取消退回、超时取消、重复使用、金额一致性。
- 生成结果没有明显重复标题。
- 每条用例的步骤和预期都能直接执行和判断。
